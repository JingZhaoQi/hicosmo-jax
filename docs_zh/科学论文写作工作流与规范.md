# 科学论文写作工作流与规范

> **基于实践经验与 Hilary Glasman-Deal《Science Research Writing》总结**
>
> 本文档适用于：天文学、物理学、计算机科学等领域的英文期刊投稿

---

## 第一部分：工作流程

### 1.1 论文写作的黄金法则

#### 🚨 最重要的三条原则

**原则一：所有结果必须来自真实程序运行**

| 禁止 | 必须做到 |
|------|----------|
| ❌ 手动编造数值结果 | ✅ 所有图表由脚本生成 |
| ❌ 使用占位符数据 | ✅ 所有数值由真实运行得到 |
| ❌ 复制粘贴未验证的旧结果 | ✅ 性能数据有明确测量条件和误差棒 |
| ❌ 基于「应该是这样」的推测填写 | ✅ 对比结果可由脚本复现 |

**原则二：每个结论性句子必须有支撑**

科学论文规范要求每个结论性陈述必须有：
- 相应的参考文献，或
- 论文中的明确逻辑推导，或
- 本文结果的直接论证

```latex
% ❌ 没有支撑的断言
Our method is significantly faster than traditional approaches.

% ✅ 有数据/参考文献支撑
As shown in Table~\ref{tab:benchmark}, our method achieves
a 17$\times$ speedup compared to the baseline under identical
test conditions (Intel i7-12700K, 32GB RAM).
```

**原则三：代码示例必须真实可运行**

论文中的每段代码都应经过实际测试，与项目文档保持一致。

### 1.2 推荐的目录结构

```
paper/
├── main.tex           # 主论文文件
├── references.bib     # BibTeX 参考文献
├── figures/           # 生成的图表 PDF
├── tables/            # LaTeX 格式表格
├── chains/            # MCMC 采样结果（如适用）
└── scripts/           # 分析与绘图脚本
    ├── run_experiments.py     # 运行所有实验
    ├── generate_figures.py    # 生成论文图表
    └── benchmark.py           # 性能基准测试
```

### 1.4 内置审稿人机制

每次重大修改后，切换到「审稿人视角」审视论文：

#### 六个审查维度

1. **科学正确性 (Scientific Validity)**
   - 物理假设是否合理？是否有隐藏的近似？
   - 数值方法是否可靠？精度是否足够？

2. **方法论严谨性 (Methodological Rigor)**
   - 对比实验是否公平？（同精度、同硬件、同数据）
   - 性能声称是否有误差棒？

3. **清晰度与可读性 (Clarity)**
   - 非专家读者能否理解核心贡献？
   - 术语定义是否清晰？

4. **科学意义 (Scientific Significance)**
   - 与现有工具相比，新增价值是什么？

5. **完整性 (Completeness)**
   - 是否有重要的遗漏？（局限性、失败案例）

6. **可复现性 (Reproducibility)**
   - 代码是否公开？版本是否锁定？

## 第二部分：论文结构与写作规范

### 2.1 Introduction（引言）四部分模型

```
1. 建立研究领域的重要性
   - 提供背景事实/信息
   - 定义标题中的关键术语
   - 介绍问题领域/当前研究焦点

2. 前人研究与贡献
   - 简要文献综述

3. 定位研究空白 (Gap)
   - 描述将要解决的问题
   - 提出待检验的预测

4. 描述本文工作
   - 目的、范围、结构、关键发现
```

#### 时态使用规范

| 内容类型 | 典型时态 | 示例 |
|----------|----------|------|
| 背景事实 | 一般现在时 | "X is composed of..." |
| 普遍重要性 | 一般现在时 | "X plays a key role..." |
| 最近趋势 | 现在完成时 | "has received much attention" |
| 特定过去研究 | 一般过去时 | "Smith (2020) showed..." |
| 研究空白（当前相关） | 现在完成时 | "little attention has been paid" |
| 本文工作 | 一般现在时 | "This paper presents..." |

**关键洞察**：从一般过去时到现在完成时的转换，表明研究空白**现在仍然存在**：
- "little attention **was paid**" → 问题可能已解决
- "little attention **has been paid**" → 问题**现在**仍存在

### 2.2 Methodology（方法）四部分模型

```
1. 提供总体介绍和概述
   - 重申研究目的
   - 说明材料/设备来源
   - 提供必要背景信息

2. 提供具体精确的细节
   - 数量、温度、持续时间、顺序
   - 说明选择理由
   - 表明采取了适当的谨慎措施

3. 将方法与其他研究联系起来
   - 引用现有方法
   - 说明方法如何比较

4. 指出问题发生的位置
   - 专业地承认局限性
```

#### 关键时态对比

| 含义 | 时态 | 示例 |
|------|------|------|
| 标准程序（通常做法） | 一般现在时被动 | "A flexible section **is** inserted..." |
| 你做的事情 | 一般过去时被动 | "A flexible section **was** inserted..." |

**关键洞察**：读者区分你的贡献与标准程序的**唯一方式**是通过时态！

#### 标记你的贡献

使用无主语被动语态时，明确标记你的工作：
- "**In this study**, the samples were collected..."
- "**Here**, the samples were collected..."

### 2.3 Results（结果）四部分模型

```
1. 重述研究目标/现有研究 + 方法论 + 概述
   - 提醒读者研究目的
   - 提供结果的总体概述

2. 邀请查看结果 + 具体/关键结果 + 比较
   - 引导读者查看图/表
   - 呈现最重要的发现
   - 与预期结果或其他研究比较

3. 指出结果中的问题
   - 承认异常或局限性
   - 解释意外发现

4. 指出结果的可能含义
   - 结果暗示或表明什么
   - 谨慎使用限定语避免过度声称
```

#### 因果关系的软化表达

软化因果陈述可降低作者责任：

| 强度 | 示例 |
|------|------|
| 强（风险高） | "X caused Y" |
| 较软 | "X contributed to Y" |
| 更软 | "X appears to have affected Y" |
| 最软（最安全） | "X may have played a role in Y" |

**因果动词（从软到强）**：
may contribute to → is associated with → leads to → causes

### 2.4 Discussion/Conclusion（讨论/结论）四部分模型

```
1. 重述之前章节
   - 重述引言（目标、空白、问题）
   - 重述方法论（理由、程序）
   - 总结关键结果

2. 定位（与现有研究的关系）
   - 展示你的工作在研究"地图"中的位置
   - 与其他研究比较
   - 确认、扩展或反驳之前的发现

3. 成就/贡献
   - 清晰陈述成就（不要害羞！）
   - 完善结果的含义
   - 解释结果在上下文中的意义

4. 局限性和未来工作
   - 专业地承认局限性
   - 建议未来研究方向
```

#### 情态动词的正确使用

情态动词修改陈述的"真值"，在讨论/结论中至关重要：

**关键洞察**：使用 "must" 实际上表明**缺乏证据**！
- "X **was** due to Y" = 你有证据
- "X **must have been** due to Y" = 几乎确定，但**没有**证据
- "X **may have been** due to Y" = 可能的原因

| 情态动词 | 含义 | 示例 |
|----------|------|------|
| can | 能力/可能性 | "This software can distinguish..." |
| may, might, could | 可能性 | "This may be due to..." |
| should | 概率/建议 | "The material should remain stable..." |
| must | 虚拟确定性 | "Contamination must be due to..." |

### 2.5 Abstract（摘要）五部分模型

```
1. 背景 / 目标 / 问题 / 本文做什么
2. 方法论 / 材料
3. 结果 / 成就 / 贡献 / 含义（最重要！）
4. 应用（如适用）
5. 局限性 / 未来工作（仅在重要时）
```

#### 摘要时态规范

| 内容类型 | 时态 | 示例 |
|----------|------|------|
| 空白/问题 | 一般现在时 | "The main problem is..." |
| 本文做什么 | 一般现在时 | "This paper presents..." |
| 方法论（你做了什么） | 一般过去时 | "Samples were prepared..." |
| 结果（确信） | 一般现在时 | "We find that X occurs..." |
| 成就 | 现在完成时 | "We have demonstrated..." |

**写摘要的黄金法则**：最后写！内容来源于其他章节。

## 第三部分：写作禁忌与历史教训

### 3.1 绝对禁止的行为

#### 1. 伪造数据（最严重！学术诚信问题）

**案例**：性能基准测试中使用 `emcee_estimate = jax_time * 4` 伪造对比数据

**规则**：
- ❌ 绝不编造对比数据
- ❌ 绝不使用未实际测试的"估算值"
- ✅ 所有性能数据必须来自真实运行
- ✅ 无法测试的工具，不要进行对比

#### 2. Toy验证与真实验证混淆

**案例**：使用高斯toy-likelihood验证采样器，但结论声称"与Planck/DESI一致"

**规则**：
- ❌ 不要用toy验证的结果声称与真实观测一致
- ✅ 采样器数值正确性验证可以用高斯toy（有解析解）
- ✅ 科学结果验证必须用真实数据
- ✅ 明确区分两层验证

#### 3. 误导性技术限制声称

**规则**：
- ❌ 不要声称不存在的技术限制
- ❌ 不要把"当前未测试"写成"技术上不支持"

### 3.2 写作风格禁忌

#### 罗列式表达（AI写作典型特征）

```latex
% ❌ AI风格（罗列式）
\textbf{Performance improvement}: A 17$\times$ speedup via JIT compilation.
\textbf{Usability}: Only three lines of code for analysis.
\textbf{Extensibility}: Modular architecture for extension.

% ✅ 人类风格（叙述式）
In terms of performance, the framework achieves a 17$\times$ speedup
in likelihood evaluation through JIT compilation. Meanwhile, the
streamlined API design ensures that users need only three lines of
code for standard analysis, while the modular architecture facilitates
future extension with new models and probes.
```

**禁止**：
- ❌ 正文中使用 `\begin{enumerate}` 列表
- ❌ 正文中使用 `\begin{itemize}` 列表
- ❌ `\textbf{标题}：内容` 的模式
- ❌ 冒号嵌套："优势一：...突破在于：..."

#### 科普化用语

**规则**：
- ❌ 不要使用科普性表述
- ❌ 不要解释众所周知的原则
- ✅ 使用专业术语

#### 数学符号格式

**规则**：
- ❌ 不要在正文中使用纯文本数学符号
- ✅ 所有数学符号必须用 `$...$` 包裹
- ✅ 使用自定义宏保持一致

### 3.3 禁止的措辞

| 禁止 | 改为 |
|------|------|
| "completely consistent" | "consistent within statistical uncertainties" |
| "proves that" | "supports", "indicates" |
| "definitely" (争议话题) | "possibly", "preliminary evidence suggests" |
| "significantly better" (无数据支撑) | "under these test conditions..." |

## 第四部分：常用词汇速查

### 4.1 建立重要性

**重要性指示词**：
- a basic/central/crucial/fundamental issue
- a challenging area
- a key technique
- a powerful tool/method
- plays a key role (in)
- of growing interest

**时间参考**：
- in recent decades
- over the past ten years
- recently

### 4.2 文献综述动词

| 常用动词 |
|----------|
| achieve, address, adopt, analyse, apply |
| argue, assume, calculate, compare, conclude |
| confirm, demonstrate, describe, develop, discover |
| establish, evaluate, examine, explore, find |
| identify, illustrate, indicate, investigate, measure |
| observe, propose, report, reveal, show |
| simulate, solve, study, suggest, test |

### 4.3 描述研究空白

**形容词**：
- ambiguous, deficient, doubtful
- ill-defined, inadequate, incomplete
- inconclusive, inconsistent, ineffective
- misleading, not well understood
- problematic, questionable, unclear
- unresolved, unsatisfactory

**关键短语**：
- few studies have...
- it is necessary to...
- little work has been done
- more work is needed
- there is an urgent need...

### 4.4 描述本文工作

**动词**：
- (to) attempt, compare, describe
- (to) discuss, enable, evaluate
- (to) outline, predict, present
- (to) propose, provide, reveal

**结构短语**：
- (is) organised as follows:
- (the) present work
- here, overview
- aim, goal, intention, objective, purpose

### 4.5 结果描述

**邀请读者查看**：
- As shown in Fig. X
- As can be seen in Table Y
- It can be seen that
- X shows/demonstrates/reveals/indicates

**比较**：
- compared to/with, in comparison with
- consistent with, similar to, in line with
- in contrast to, unlike, differs from

**含义（限定语）**：
- This suggests/indicates/implies that
- These results point to
- may/might/could
- it is possible that

### 4.6 讨论/结论

**定位（与其他研究的关系）**：
- consistent with, in line with, in agreement with
- extends, confirms, supports, corroborates
- contradicts, challenges, differs from
- the first of its kind, to our knowledge

**成就（强）**：
- compelling, dramatic, excellent, remarkable
- striking, surprising, unprecedented, unique

**成就（中等）**：
- accurate, effective, robust, novel
- straightforward, successful, valuable

**局限性/未来工作**：
- should be validated/replicated/verified
- further work is needed/planned
- remains to be determined
- promising, encouraging, holds promise

## 第五部分：检查清单

### 5.1 提交前总检查

#### 科学内容
- [ ] **核心贡献明确**：读者能在 30 秒内理解「这篇论文解决了什么问题」
- [ ] **创新点有说服力**：与现有工具的差异化价值清晰
- [ ] **结果可复现**：提供完整的代码、数据、脚本
- [ ] **数值结果一致**：论文中引用的数值与实际运行结果完全匹配
- [ ] **与文献对齐**：约束结果与官方发布在统计误差内一致

#### 技术准确性
- [ ] **代码示例可运行**：论文中的每段代码都经过实际测试
- [ ] **公式无误**：所有数学公式已核对，下标/符号一致
- [ ] **图表清晰**：分辨率足够、标签可读、配色专业

#### 写作规范
- [ ] **每个断言有支撑**：结论性句子有参考文献、推导或数据支持
- [ ] **措辞准确**：无夸大（「proves」「completely」需核查）
- [ ] **逻辑连贯**：章节之间有清晰的逻辑过渡
- [ ] **语法正确**：无拼写/语法错误
- [ ] **格式规范**：符合目标期刊投稿要求

#### 可复现性
- [ ] **commit hash 真实**：论文中的版本号指向真实可访问的代码
- [ ] **依赖说明完整**
- [ ] **数据来源标注**：所有外部数据集有 DOI 或官方链接
- [ ] **随机种子固定**：结果可精确复现

### 5.2 修改论文前检查

每次修改论文前，检查：

- [ ] 是否有编造的数据或"估算值"？
- [ ] 是否声称了不存在的技术限制？
- [ ] 章节/子节结构是否均衡？
- [ ] 是否有 enumerate/itemize 列表需要改成段落？
- [ ] 是否有 `\textbf{标题}:` 的模式？
- [ ] 是否有科普化表述？
- [ ] 硬件信息是否真实？（用系统命令验证）
- [ ] 数学符号是否都在 `$...$` 内？
- [ ] toy验证和真实验证是否区分清楚？
- [ ] 关键外部数值是否有引用？
